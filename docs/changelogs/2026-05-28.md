# Android 16 KB page size compatibility

Google Play requires all apps targeting Android 15+ to support devices with 16 KB memory page sizes starting **November 1, 2025**. New app submissions and updates that ship 4 KB-only native libraries are rejected.

Oky picks up 16 KB support through the Expo SDK 52 → 54 upgrade ([#241](https://github.com/Oky-period-tracker/oky-app/pull/241)), which brings React Native 0.81 + React 19. RN 0.81 is the first RN release where the bundled JSC/Hermes engine and all first-party native libraries are built page-size-agnostic, so the resulting `.so` files load on both 4 KB and 16 KB devices.

## Changes

- Expo SDK upgraded from 52 to 54
- React Native upgraded from 0.76 to 0.81
- React upgraded from 18.3 to 19.1
- `@react-native-firebase/*` upgraded from v20 to v22 (required for RN 0.81's Swift `AppDelegate`)
- `react-native-reanimated` upgraded from 3.16 to 4.1
- Entry point moved from `node_modules/expo/AppEntry.js` to a project-owned [app/index.ts](app/index.ts)
- [app/app.config.js](app/app.config.js) now patches `expo-build-properties` at prebuild time to drop `useFrameworks: "static"` and inject `modular_headers: true` for Firebase's Obj-C dependencies (`FirebaseCore`, `FirebaseCoreExtension`, `FirebaseInstallations`, `GoogleDataTransport`, `GoogleUtilities`, `nanopb`). Required for RNFB v22 to compile under RN 0.81's prebuilt React-Core.
- [app/metro.config.js](app/metro.config.js) sets `resolver.unstable_enablePackageExports = false` to keep current dependency resolution behaviour under Metro's SDK 54 defaults.
- `ios` and `podinstall` scripts in [app/package.json](app/package.json) now export `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8` so CocoaPods 1.15 / Ruby 3.3 can read the Podfile on a fresh macOS shell.
- New build documentation at [docs/ios_build.md](docs/ios_build.md).

## Required Actions

- **Wipe and reinstall the native projects** from `app/`:

  ```bash
  rm -rf ios android node_modules
  yarn
  npx expo prebuild --clean
  ```

  Do not keep the old `ios/` and `android/` folders — they were generated against SDK 52 and will not rebuild cleanly against SDK 54.

- **Rebuild all release artefacts** (AAB / IPA) against this branch before submitting to Google Play. Older AABs produced from SDK 52 contain 4 KB-only `.so` files and will be rejected by Play after the November 1, 2025 cutoff.

- **Verify 16 KB compatibility locally** before submitting.

- **EAS / CI**: clear any cached `ios/` or `android/` directories in the build profile and re-run `eas build` so the workers regenerate the native projects against SDK 54. In `eas.json`, it is preferred to use `app-bundle` as `buildType`.
